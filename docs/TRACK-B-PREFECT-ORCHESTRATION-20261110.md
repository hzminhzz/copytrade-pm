# Track B v2 — opt-in local Prefect 3 research workflow

**Status:** Engineering integration only. No persistent scheduler, Prefect Cloud, live Grafana route, source/PM03/04 changes or trading authority.

## Purpose

Run the *existing* deterministic Pydantic Track B health computation for up to 16 separately pinned private assessments. This is a batch evaluator, not a source collector or a competing finance calculation. The original assessments must already be generated by independently reviewed Track B source/census/PM03 readers; orchestration does not authenticate them.

Each input and output is private and immutable. On re-invocation after a crash, the same completed report is re-verified and reused. A failed job does not delete another job's successful artifact.

## Setup

Use an isolated nonproduction checkout and **do not** install an always-on Prefect service:

```bash
uv sync --frozen --extra prefect --group dev
uv run --frozen --extra prefect copytrade-pm-track-b-prefect --help
```

Prefect is pinned to `3.9.2` and isolated behind `pyproject.toml [project.optional-dependencies].prefect`. The project does not depend on PydanticAI or a remote Prefect server. Prefect 3 may start a temporary loopback server for the duration of a local run. Prefect server analytics are disabled during each local run. External `PREFECT_API_URL` / `PREFECT_API_KEY` configuration fails closed (including active Prefect profiles).

Prepare **outside the repository**:

- Private, operator-owned input folder `0700` containing a prior sealed `strategy_health_assessment_v1` file `0600`.
- Optional `OpportunityEvidence` JSON array and optional predeclared `WeeklyLook` JSON; each `0600`, pinned by original byte SHA256. These are *assertions*, not independently authenticated proof.
- Private, owner-created **existing** output directory `0700`, isolated from the live source, paper and Grafana roots. Do not point to the running journals or `/evidence`/health publisher volume.
- Original pinned manifest `0600` with absolute file paths, SHA256 hashes and 1–16 jobs. Do not put keys, private JSON, or a broker route in the manifest.

Example (illustrative paths, replace SHA strings with actual `sha256sum` outputs):

```json
{
  "schema": "track_b_prefect_job_manifest_v1",
  "output_dir": "/operator-private/track-b-prefect-staging",
  "jobs": [
    {
      "report_path": "/operator-private/original/assessment.json",
      "report_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
      "evidence_path": null,
      "evidence_sha256": null,
      "weekly_look_path": null,
      "weekly_look_sha256": null
    }
  ]
}
```

```bash
sha256sum /operator-private/original/manifest.json
uv run --frozen --extra prefect copytrade-pm-track-b-prefect \
  --manifest /operator-private/original/manifest.json \
  --sha256 <exact-manifest-byte-sha256>
```

**Result:** a sanitized JSON receipt with job counts, report content SHA and `PUBLISHED` or `EXISTING_VERIFIED`. Operator-private output is named `<report-blob-sha256>.json`, `0600`, no-clobber. `trading_authorized`, `source_finance_authenticated`, `scientifically_qualified`, `shadow_deployed` are always `false`.

**Important:** output is **not** a signed Grafana publication. Only the separate original private publication binding with a trusted out-of-repo Ed25519 key, an independently pinned original v1 rollback snapshot, authenticated ingress and deployment authorization may promote a redacted projection. No default production publication exists.

## Proof-bound original evidence — separate opt-in one-job mode (2026-11-11)

The original `copytrade-pm-track-b-prefect` manifest interface remains unchanged. A separate command handles one **independently audited signed-original Track B reconciliation**: `copytrade-pm-track-b-evidence-prefect`. It uses the original `track_b_evidence_reconcile_request_v1` manifest from the proof-bound reconciler (not the old pre-sealed assessment jobs). An unaudited request cannot enter this Prefect path.

```bash
uv run --frozen --extra prefect copytrade-pm-track-b-evidence-prefect \
  --manifest /owner-private/original/reconcile-request.json \
  --sha256 EXACT_MANIFEST_FILE_SHA256 \
  --trusted-source-public-key-sha256 OUT_OF_BAND_SOURCE_KEY_SHA256 \
  --trusted-auditor-public-key-sha256 OUT_OF_BAND_AUDITOR_KEY_SHA256
```

The private manifest must pin the original signed V4 packet, its source public key, an independently signed audit anchor, its original auditor public key, source journal and an existing owner-owned private output directory. Every retry rereads the exact SHA-pinned request and delegates proof verification/assessment to `strategy_evidence_reconciler.reconcile_manifest`. A single local task returns only sanitized SHA/status fields. There is no persistent job manager, automatic source acquisition, second financial authority, public release, or trading permission. No remote Prefect API or telemetry analytics are allowed. Full-chain initial source audits are still allowed **only on small, isolated, operator-confirmed backups**; live large-journal full scans are not an optional fallback.

This command is an engineering experiment. Original 0911 operational restoration, original market/PM03/04 completeness, scientifically comparable follower economics, independently signed publication and Grafana acceptance remain separate prerequisites.

## Reliability and rollback

- Rerun the exact pinned manifest after an interruption. Completed SHA outputs return `EXISTING_VERIFIED`. There is no automatic process resurrection without an independently deployed worker.
- If an input is unavailable, source finance is unknown, or its hash mismatches, stop; do not substitute a different file or the current latest event.
- If one of several jobs fails, earlier successful jobs remain independently sealed. The Prefect flow overall is FAILED rather than pretending all succeeded.
- Only transient local I/O has bounded Prefect retry. No retry of source receipt ingestion, external financial writes, unknown broker outcomes or validity errors.
- Rollback is simply **do not invoke** the new optional CLI. Existing source and paper services remain pinned; keep private evidence for audit. Removing a staging artifact requires a separate operator retention/cleanup decision.
- Monitor disk budget before larger cohorts. This optional workflow is not a fix for the existing large V4 SQLite WAL/producer contention.
- A process-local Prefect result store is not an independent immutable source, finance report, signed release or scientific certification.
