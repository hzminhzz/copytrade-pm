# Grafana operational read model — Phase 2 correction, 2026-11-08

**Scope:** draft PR #195 against parent #180, independent architecture review on 2026-11-08. This is source and disposable staging evidence, **not** production installation or permission to trade.

## One presentation-evidence authority

`DashboardReader` continues to delegate registry identity and Guardian finance, execution, and reconciliation to their native authorities. `grafana_capabilities` owns fixed bounded capability fields, explicit completeness, row/section qualification, source-clock checks, freshness downgrades and operational incident classification. `evidence_plane` owns atomic publication, SHA integrity verification, and the fixed legacy account-risk schema. The read-only HTTP gateway consumes those validated facts; it does not interpret Guardian finance or query any native source.

The publisher reads independently supplied owners sequentially, assigns `generated_at` after its read cycle and checks every capability's source and row timestamps against that boundary. A clock from an earlier overview query is **not** a valid cutoff for later capability reads. An impossible source clock encountered while building an individual capability is quarantined as `CAUSALLY_INVALID_SOURCE_CLOCK`; an externally supplied tampered/future-dated generation is rejected by the strict publication validator. No source timestamp is overwritten or silently promoted to the current time.

The `grafana_operational_capabilities_v1` representation now carries `completeness` as `COMPLETE`, `EMPTY`, `INCOMPLETE`, or `UNAVAILABLE`, separately from source qualification status and operational severity. Verified empty means an authenticated, coherent, timestamped **absence of rows**, not a fabricated `UNAVAILABLE` placeholder. A missing authority remains unavailable. Parent/child contradictory VERIFIED claims fail validation. Expired publications and source rows cannot retain verified child grades even when the parent was already degraded or unknown. A corrupt generation still fails closed as a whole; a native source exception quarantines only its own capability.

The public projection does not reconstruct NAV, broker acceptance, receipts, portfolio deployment or risk budgets. Missing owner-verified finance remains null, never zero. Research selection is not portfolio run-state. Viewer requests do not perform native reads.

## Execution and alerts

T+300s scheduled entry and the actual decision, durable intent, broker acceptance, owner-confirmed fill and reconciliation are distinct clocks. Duplicate intents under the same decision and market are different from multiple fills of one intent. Actual last-fill delays beyond the explicitly provisional 5-second presentation exception bound produce `FILL_LATE_BROKER_RECEIPT` only with owner-verified fill IDs. Without broker acceptance or reconciliation, the read model does **not** claim verified execution. Truncated receipts remain unqualified. This classification is **presentation only**; no execution policy changed.

The three existing Grafana-managed backend alert rules remain browser-independent. Generation failure uses immutable publication age. Account-risk evidence faults indicate stale or blocked critical financial evidence, without treating optional portfolio membership as a critical finance metric. An operational incident requires verified abnormal operational state or an actual execution exception, not simply a missing optional source. Expected missing source authority remains explicitly UNAVAILABLE in panels, without perpetually firing the operational incident rule. This distinction does **not** mean missing broker/finance is healthy or trading is permitted. External contact points and delivery remain unconfigured.

## Verification and limitations

New public-interface adversarial tests cover stale child evidence under unknown parent, future capability/row clocks, sequential read-cycle clock ordering, coherent verified empties, contradictory grades, a six-fill 24-minute-late execution, absent acceptance, truncated receipts, source exception isolation, optional account membership, and incident recovery. The existing first-phase compatibility, fixed read-only HTTP requests, atomic publication, and unchanged numerical zero semantics are exercised by existing tests.

Disposable Grafana 13.3.0 / Infinity 4.1.6 staging on HTTPS 8444 successfully ran all five dashboards at 1280×800, 390×844 and 430×932. All fifteen browser checks asserted actual source rows and no viewport overflow. Owner Viewer, denied admin routes and mutations, isolated Docker networks, one-way Infinity reads and unavailable finance were reverified through live security acceptance. Initial browser run exposed an invalid use of the overview timestamp as a later capability cutoff; this was fixed and all fifteen viewports passed in a rebuilt staging environment. Staging was then torn down, including its Tailscale route and containers. Production HTTPS 8443 and existing monitored service PID/restart counts were unchanged.

Still **not independently accepted**: owner-authorized canonical SQLite plus protected Guardian capture integration in the isolated publisher; genuine broker acceptance and reconciliation evidence; full real backend alert missing/corrupt/timeout/recovery/restart and delivery observations; signed/pinned installed rollback verification; actual non-owner Tailscale peer denial (#184); measured Phase 3 cold-render p95 target and independent visual review; protected Guardian journal continuity/cadence. Do not mark #185–#189 or #190 complete based on source tests. This PR remains draft and unmerged.
