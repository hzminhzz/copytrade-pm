# Canonical five-minute runtime and source outbox

This is an implemented, opt-in source transport in the existing selected-position observer. It is not an installed source cutover. The installed first-known T0+300 service and its historical evidence retain their original contract.

## Source configuration

The existing command `python -m copytrade_pm.pm_v4_selected_positions` accepts `--source-mode CHECKPOINT_REST_V3`. The default remains `LEGACY_WS`. REST mode requires `--checkpoint-config` and `--checkpoint-config-sha256` before any source acquisition or state-directory creation. `--checkpoint-once` provides a bounded collection through the same path.

The private JSON configuration has these required fields:

| Field | Contract |
| --- | --- |
| schema | cwsa_observer_config_v1 |
| policy | CwsaPolicy: cwsa_utc_5m_v3, original measurement SHA, and every approved SamplingLimits value |
| scopes | Exact selected source IDs, address hashes, native account/DEX generations and selected-roster hash |
| first_checkpoint_ms | Explicit prospective UTC boundary divisible by 300000 |
| workers | Explicit bounded request concurrency |
| weight_per_second | Explicit request pacing within the existing read-only measurement budget |

There are no default freshness, skew, acquisition or publication limits. A hash-pinned file does not establish empirical qualification or replace approval of its numerical policy. No production configuration is generated by this change.

Selection uses the existing sealed registry loader. All sixteen prospective paper scenarios use the existing campaign manifest and SHA options; their deduplicated parent roster must exactly match the configuration. A follower mandate replacement does not change native source generations.

The existing entrypoint takes one source-authority process lease, chooses one transport mode, and uses the existing PaperJournal and SerialWriter. REST collections can overlap within the declared worker budget; each completed wallet is published durably without waiting for slower wallets. Actual native, acquisition and publication clocks remain distinct. On restart, the journal's next checkpoint owns scheduling. Missed boundaries produce explicit GAP/UNAVAILABLE transitions. No historical native request can manufacture an earlier observation.

No source scheduler service, financial journal, Guardian, credentials, or broker route was added.

## Signed outbox

The existing `python -m copytrade_pm.v4_source_spool` accepts `--wire-version 3`, the same pinned configuration, registry/campaign selection, and independently provisioned source signing/public-key paths. Wire v1 remains its default.

Wire v3 reads the existing source journal in SQLite read-only mode. Each immutable packet includes original native response bytes, source scope/policy, and canonical transitions. The outbox verifies retained packet signatures and exact source-journal prefixes to recover published cursors. There is no mutable cursor that can erase a publication after a crash. Identical repeated capture emits no new packet. Missing source registration is reported per source; trust drift, missing published history, equivocation or a legacy-spool mixture blocks publication.

A single invocation exports up to the existing 256-transition packet bound per source. Repeated invocations drain a backlog without changing source opportunity timestamps. The protected receiver independently verifies the original native proof and expires old opening candidates.

## Verification and limits

The targeted source/runtime/export/spool/legacy-selection gate passed 45 tests before commit. Tests cover the existing native collector, complete all-DEX scope, exact clocks, canonical source transitions, restart gaps, source lease exclusivity, explicit configuration, immutable repeated publication, tampered history, and source database preservation.

Synthetic timing values used in tests are not production thresholds. The read-only capacity measurements in `CANONICAL-5M-CAPACITY-317.md` remain separate evidence. Approved numerical limits, prospective checkpoint mandates, sustained tail/shared-IP measurements and protected source-cutover authorization are still required before operational promotion.
