**State: ENGINEERING VERIFIED LOCALLY; unsigned candidate only. Not an installed or authorized paper run.**

The original P1/P14 research portfolio versions were SHA-sealed before
their private Phase-4 alias evidence was recorded. Their historical wallet IDs
remain **post-seal**, even where today's registry points to the same address.
Never update original `portfolio_memberships`, `portfolio_seals`, historical

## Verified command

Use the existing paper identity capability, not a new database or signer:

```bash
uv run --frozen --group dev copytrade-pm capabilities show paper.identity
REG="$HOME/.local/share/copytrade/registry/wallet_registry.sqlite"
PRIMARY="/home/quant/dev/copytrade-pm/data/wallet_fills_90d"
SECONDARY="/home/quant/dev/copytrade-pm/data/nansen_smart_money_fills_90d"
uv run --frozen --group dev copytrade-pm-paper-registry-audit \
  --registry "$REG" --primary-dir "$PRIMARY" --secondary-dir "$SECONDARY" \
  --portfolio P1 --prospective-reseal-preview
uv run --frozen --group dev copytrade-pm-paper-registry-audit \
  --registry "$REG" --primary-dir "$PRIMARY" --secondary-dir "$SECONDARY" \
  --portfolio P14 --prospective-reseal-preview
```

The default CLI (without the preview flag) remains the original historical
frozen-seal audit. `--as-of` with the preview is diagnostic only; it cannot
backdate a later first-known signing/import event. An invalid, future, or naive
cutoff fails closed.

Each preview rechecks the original sealed members, current private locator
SHA and full native Hyperliquid address, then finds an unambiguous wallet
alias recorded **no later than** the selected UTC cutoff. Conflicting alias
identities, address mismatch, duplicate canonical wallet, missing provenance,
unsafe whale locators and future times fail or block. It never changes SQLite.

At the observed live 2026-11-05 UTC snapshot, both previews returned
`SIGNER_REVIEW_REQUIRED`, P1 **3/3** and P14 **5/5** current PIT
alias-to-address matches. Original P1 3/3 and P14 5/5 **post-seal historical**
identities were still blocked. This is a time-specific, read-only
diagnostic, not an actual signed reseal. Rerun before acting.

## Independent signed research selection — still required

`unsigned_candidate` is a research-only structural proposal using the
existing `copytrade_signed_research_selection_v1` format, under fresh
namespace-qualified IDs `paper.prospective/P1-YYYYMMDD` and
`paper.prospective/P14-YYYYMMDD`. The date labels the preview, not the
future signer's real first-known time. Both are `RESEARCH_CANDIDATE` with
no ranked priority; they do **not** replace the approved E6/E2 ranking or
the original P1/P14 identity. Membership is sourced from their original
frozen aliases, not inferred from vendor statistics.

A separate, authenticated operator must review the exact candidate,
decide portfolio membership and version, and sign with an independently
trusted Ed25519 key. No private signing key or forged operator signature
is generated by this preflight.

Use the already supported `copytrade-wallet-registry signed-selection`
preview with a separately supplied private manifest, signature,
trusted public key and **externally reviewed** key SHA256. The signed catalog
records its true local first-known import time, never the original Gemini
selection date. Its `--apply` path requires independent permission,
verified backup, source SHA and an explicit cutover decision; it is not
performed by this preview.

**Further independent gates** after any signed selection include: correct
run manifest explicitly naming the **new** selected version and SHA,
complete first-known parent/subaccount/DEX/collateral NAV, signed positions
and hedges, market orderability/volume/costs, PM-03/04 cash/margin/risk,
protected root-owned processes and watchdog. A signed research selection
alone does not grant those or start a P1/P14 financial worker.
