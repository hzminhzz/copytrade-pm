# V4 position-first SQLite recovery and compact evidence (issue #292)

**Scope:** read-only SHADOW 0811 and 0911, each separately. **No broker/Guardian operations.** This document does not authorize a cutover or deletion. Do not run maintenance on an active journal.

## Version compatibility

- Historical `paper_observer_stream_event_v1` and `source_receipts` bytes, receipts, chain hashes, sequence and first-known timestamps remain immutable. An unchanged/duplicate frame on the new release produces no economic source receipt/event. A separately bounded health row reflects freshness and clocks; it is not a financial event.
- New V4 `paper_observer_stream_event_v2` events retain original raw-wire SHA and canonical frame SHA. Original UTF-8 native-wire bytes are zlib-compressed once under private `source-evidence-v2/<prefix>/<raw_sha>.zlib`, fsynced and published before the SQLite stream references the path. Missing/corrupt sidecar fails proof validation; backup must include the complete sidecar tree.
- The indexed locator is transactionally appended with new receipts. Historical unindexed v1 journals can use the legacy read-only scan until a separately verified, offline additive `backfill_verified_source_locators()` migration. That migration preserves original stream heads; execute only after quiescence and independent restore checks. Never assert that a partial locator index is authoritative.
- **Historical source receipt v1 rows are not compacted** by this release. Old main-DB pages will not shrink via WAL TRUNCATE. Archive/rebuild and retention require separate verified read-through compatibility, preserved finance references and explicit retention authorization.

## Evidence and preflight for each journal (0811 first only if dependencies permit)

1. Identify the exact currently pinned source and paper release revisions, `systemctl --user show ... -p MainPID -p ExecStart -p NRestarts` and `lsof`/`/proc/<pid>/fd` for **all** SQLite DB, WAL and SHM openers. Record source stream heads, receipt cursors, epoch/gap, ledger heads, pending intents, unresolved held exposures, known readers and replay result. Record CPU quota/throttle counters, current WAL size, source freshness and free disk.
2. Verify the release artifact and its intended dependency versions against the reviewed commit and rollback release; confirm no concurrent Track A writer is operating. Compare mainline source/stream and paper interfaces with the installed version. A green unit test is not proof of installed compatibility.
3. Verify independent storage capacity **before any copy**: include current DB+WAL, independent online-backup image, restored copy, sidecars and reserve, one journal at a time. Root free space observed on 2026-11-10 was only ~45 GB and is not approval for simultaneous 0811+0911 backups/rebuilds. Prefer externally verified backup storage when insufficient.
4. Quiesce every relevant paper reader first (0811 P1/P14/P16 and any extra readers; 0911 16 portfolios and pydnative readers), then corresponding producer. Hold an explicit no-new-risk fence; record exact stop timestamps and last verified chain/financial heads. Preserve any pending or held exposures; do not fabricate a flat.
5. Use Python `sqlite3.Connection.backup` or SQLite backup API to create a **new** backup path, never overwrite the live journal or financial journals. Independently restore to another isolated destination. On restored DB, run `PRAGMA integrity_check`, `PRAGMA foreign_key_check`, full source/stream-chain proof and financial replay parity. Include every v2 sidecar and verify raw SHA bytes. A backup command succeeding without independent restore is **not sufficient**.
6. Only when there are zero writers/readers referencing that DB, execute `PRAGMA wal_checkpoint(TRUNCATE)` with bounded busy timeout. Record SQLite `(busy, log, checkpointed)` and after-size. Require `busy=0` and observed WAL shrink; a rogue reader or incomplete checkpoint **blocks** recovery. Never unlink or manually truncate active `-wal` or `-shm`.
7. If permitted, perform verified additive v1 locator backfill offline. Verify original v1 bytes and stream head SHA unchanged. Never run historical pruning or VACUUM INTO merely to report disk savings.
8. Install and start *only* independently reviewed pinned source code with full private sidecar preservation, then require a non-actionable new baseline. Reopen paper readers one by one; verify source streams, first-known clocks, T+300 non-resetting intents, independent ledger heads, genuine risk reductions and halted new risk until proven continuity.
9. Restore the prior pinned release only with schema/sidecar compatibility verification and preserved immutable financial/source heads. If a step fails, keep all original journals, backups and PIDs evidence intact; report exact blocker and run no real broker order.

## Benchmark/monitoring contract

For identical official-shaped frame workloads record: processed frames by classification; full source/stream rows per 10k unchanged; compact sidecar bytes; main DB and WAL bytes before/after; observer/paper CPU seconds; cgroup throttling; oldest source read transaction/lock waits; checkpoint counters; proof p50/p95 and `EXPLAIN QUERY PLAN` (indexed receipt lookup on qualifying new streams); restart count and gap/freshness; synthetic PM03/04 ledger replay parity. Distinguish isolated engineering measurements from actual prospective follower economics.

**Release status contract:** IMPLEMENTED, TESTED, MERGED, DEPLOYED, RECOVERED, SCIENTIFICALLY QUALIFIED and TRADING AUTHORIZED are distinct. Missing review, disk, backup/restore, compatibility or source continuity evidence blocks live maintenance; it does not invalidate already tested isolated engineering work.
