**Status:** Vike transport observation, independent REST census, pure candidate reducer and an isolated **durable candidate-only original-backed SQLite projection** implemented/tested; **no V4-admissible reconciled complete-position source, no 14/14 continuous coverage, no V4 source cutover**. Authoritative design: [Vike-first ADR](decisions/2026-11-11-vike-first-wallet-source.md). Finance and timing contract: [position-first ADR](decisions/2026-11-08-position-first-t300.md).

## What exists

- `pm_vike_selected_fills.selected_campaign_wallets`: resolve the complete frozen 16-portfolio cohort to exactly **14 unique selected parent accounts**, checked against the canonical SQLite registry and private SHA-pinned campaign. A historical campaign alone is not a signed trading selection.
- `pm_vike_selected_fills.run_selected(... include_positions=True)`: opt-in single Vike WebSocket for `hl.fills` and `hl.positions`, both with `min_usd:0`. Independent cursors, strict event IDs, actual receive clocks, retrospective recovery tagging, atomic raw observation/checkpoint, deduplication, explicit gap tracking. Existing 0811 fill-only service is unchanged unless separately released.
- `pm_vike_position_observations`: new tables in the existing selected-fills observation SQLite, original wire SHA and canonical event SHA, position notification parsing, per-channel ACK and latching GAP. Every position observation is **NOT_COMPLETE_BOOK** and **NOT_PAPER_ELIGIBLE**. A duplicate original event with a different transport cursor must not mutate financial state.
- `pm_vike_official_parity`: bounded official HTTP `perpDexs` + per-DEX `clearinghouseState` complete selected-parent REST census, strict scope and native Decimal parsing from existing E4, provider-time skew ceiling, original raw response SHA validation. Private `0700` archive stores each original response and SHA-sealed `0600` manifest. The aggregate cohort report is independent audit evidence, not a continuous native stream or paper signal.

## Independently replayed original-source proof and pure candidate reducer (follow-up)

An additive nonactivating engineering increment adds `pm_vike_official_parity.verify_archived_official_census`: the consumer must know the expected wallet and SHA of the archived manifest, re-hash **every original official response**, reconstruct the complete per-DEX state from the original bytes through the existing parser and compare all market quantities, times and DEX hashes with the recorded report. A re-derived report alone is not acceptable proof. On the original private 2026-11-11 campaign archive, all **14/14** parents independently verified, with **127** nonzero native position rows across their complete selected-parent DEX scopes (sum of positions across parents, not necessarily unique instruments).

`pm_vike_reconciled_positions` is a strict, pure Pydantic **candidate** position-state reducer: verified initial REST census is always non-actionable; monotonic Vike event cursor and source time, explicit native quantities, position prestate and action, selected account/DEX and locally known event clocks are checked. Provider GAP, retrospective event, mismatch or epoch change fail closed. An independently verified later census can mark a matching candidate `RECONCILED_CANDIDATE_NOT_PAPER_PROOF`, **not** produce a V4 `OBSERVED_STATE_CHANGE`. This is testable deterministic logic, not a durable account-source event journal or a replacement for the existing official stream proof. The existing Pydantic/PM03/04 contracts and paper service remain unchanged.

## Isolated crash-safe candidate journal (new nonactivating increment)

`pm_vike_reconciled_journal` adds bounded indexed per-account candidate head/history in the **same** SQLite journal as the original Vike notification rows. One IMMEDIATE transaction commits the projected Pydantic checkpoint and its chain-linked provenance. Each projected event must resolve to the **original persisted wire** and match its SHA, normalized event hash, original account and cursor; duplicate IDs are idempotent, and conflicting or retrospective events fail closed. Initial/reconnect baselines require a separately reverified original-byte official REST archive, a new epoch and complete selected DEX census. Later official archives can reconcile candidate books but never admit paper new risk. A strict bounded audit checks every projected hash-chain link and original notification bytes. No existing paper or official journal is edited by this engineering increment.

The new module is a **library/API only**, not a running Vike-to-V4 admission adapter or a collector deployment. In particular, this candidate journal does **not** create an `OBSERVED_STATE_CHANGE`, does **not** impersonate `OFFICIAL_WS`, and does **not** replace or bypass `verify_official_position_transition`. The canonical paper worker remains on the original official 0911 source database. Caller must manage source subscription and independent archives, and cannot lift the preexisting provider GAP without a new independently verified epoch. Tests cover original-byte tamper, duplicates, restart, provider GAP, rejected retrospective events, native-prestate mismatch and bounded replay.

**Fresh provider investigation:** Read-only Vike stream registry and retained REST stream events on 2026-11-11 confirmed `hl.positions` is exposed with `min_usd:0`, but the provider returned a `channel_idle` GAP from **2026-11-10T15:10:09.797Z** to **2026-11-11T10:26:21.332Z** at cursor `1794392781332-0000`. Later unrelated Vike position notifications exist, which prove channel capability, **not** selected cohort completeness. One Vike stream connection for the selected fill collector was open; the earlier two-subscription canary ran about 69 seconds and delivered zero events, with no independent 14/14 Vike position parity. A further **read-only, server-validated Vike filter probe** resolved exactly 14 frozen campaign parents from SQLite and requested `hl.positions` with `wallet=[14 selected]`, `min_usd=0` and `since_ms=2026-11-11T10:26:00Z`. The retained first page returned **zero selected position events, one earlier `channel_idle` GAP and `has_more=false`**. This proves neither that quiet accounts were continuously monitored nor that every true position change would have arrived; it remains **0/14 independently qualified continuous sources**, not a parity pass. The probe used provider REST and did not replace the active Vike collector connection. A rolling official REST census cannot qualify that absence. This is a **source-cutover blocker**, not license to relax provenance.
